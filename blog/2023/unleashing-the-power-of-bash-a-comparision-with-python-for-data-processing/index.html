Excerpt:

Recently, while working with a large text dataset, I found myself diving deep into the world of bash scripting to unlock the potential for mining patterns, extracting information, and parsing data.

As a Pythonista, I predominantly rely on Python for scripting and enterprise-level development. However, this experience with bash made me realize the true power that developers can harness by incorporating bash into their development pipelines.

What is the Problem I am solving?

First, let’s look at a folder structure to understand the Problem.

In my specific task, I needed to do the following -

  • Traverse directories within parent folders.
  • Find XML files within the directories.
  • For each XML file:
    → Locate a specific node containing a PDF embedded in Base64 format.
    → Extract the Base64 data.
    → Export the PDF.
    → Split the PDF into individual images representing each page.
    → Perform OCR using Tesseract on each image to extract text.
    → Merge the text splits into a single file representing the PDF.

Fire in the Hole — BASH!

I decided to tackle this task using bash, leveraging its capabilities to run the subroutine on the entire Dataset. The execution time for the task was approximately 132 minutes. Curiosity sparked within me, and I wanted to compare the performance of bash against Python for accomplishing the same objective.

Oh, Python, the Groovy Serpent of Codes!

To convert the bash script into Python, I sought the assistance of ChatGPT, guilty as charged considering — time is money. The bash-specific CLI tools such as tesseract and pdftoppm were replaced with their Pythonic counterparts: pytesseract and pdf2image, respectively. I made some adjustments to the script to address issues that a robot cannot handle.

Some Hurdles I came to Across

Although the performance disparity is noticeable, it is crucial not to hastily conclude that bash is the ultimate solution for every task. It is essential to consider some challenges associated with bash -

  • Limited debugging capabilities
  • Requiring extensive use of echo/print statements for debugging
  • Less comprehensibility for other developers, resulting in longer ramp-up time to understand the code
  • The syntax is quite ugly (there — I said it) compared to Python.

Bash vs. Not Bash Trade-Off:

Bash can be a suitable choice in scenarios where you need to automate quick tasks that would typically be done with Python. The decision between bash and Python depends on your familiarity and experience with both languages. However, here’s an unorthodox recommendation: for tasks that are algorithmically simple yet computationally intensive or I/O bound, give bash a shot. You can even write a Python script initially and then convert it to bash to benefit from the performance boost.
